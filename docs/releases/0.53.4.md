# qfit 0.53.4 — Mapbox style improvements

Release preparation for local desktop testing in QGIS 3 and QGIS 4. The GitHub
release remains a **draft** pending the maintainer's desktop acceptance.

## Changes since 0.53.3

- Light: fewer repeated road labels, source-based road widths, improved ordinary
  national-boundary foreground/background treatment, and bounded open-font
  mappings.
- Light: restored source-requested English/local names for countries, major
  settlements, roads, waterways, natural features and POIs; airport code/name
  branches now follow the source style.
- Outdoors: improved road, bridge and tunnel widths and road-label sizing;
  improved country-specific shields and suppression of orphaned shields.
- Expanded real-QGIS regression coverage, reproducible font-enabled Docker
  environments, and map/PDF comparison provenance and diagnostics.

The maintainer accepted this baseline and requested closure of
[#1453](https://github.com/ebelo/qfit/issues/1453) and
[#1462](https://github.com/ebelo/qfit/issues/1462). Further style-parity iteration
is stopped. This is not a claim of pixel-perfect parity or completion of every
cartographic coverage cell. No new rendering changes are made by the release
preparation itself.

## Packages

| Package | QGIS metadata compatibility |
| --- | --- |
| `qfit-0.53.4-qgis3.zip` | QGIS 3.28–3.99 |
| `qfit-0.53.4-qgis4.zip` | QGIS 4.0+ |

Both packages use the same source tree. Automated runtime validation targets
QGIS **3.44.11 / Qt 5** and **4.2.0 / Qt 6**; these checks do not certify every
older supported version or the user's desktop environment.

## Accepted limitations

- Native QGIS rendering remains an approximation of Mapbox GL. Label eligibility,
  language coverage, collisions, typography and some zoom/filter transitions
  still differ; the [Light assessment](../light-cartographic-assessment.md)
  preserves scoped findings and untested areas.
- QGIS 4 can change map detail and label placement with output density at the
  same physical scale. PDF repeatability/fidelity differences remain unresolved.
- Plugin ZIPs do **not** bundle or install fonts. The Docker comparisons use
  Barlow Regular/Medium/Italic/Bold and Noto Sans. Desktop font availability can
  change appearance; missing Barlow retains the existing fallback. See the
  [font policy](../mapbox-font-policy.md) for provenance and installation scope.
- Desktop, accessibility and broader overlay/output coverage is incomplete.
  Closure records acceptance of this baseline, not passing evidence for those
  untested cases. New concrete problems can be filed as focused issues.

## Local QGIS 3 and QGIS 4 test plan

1. Keep existing projects safe by testing in a separate QGIS user profile in each
   version. Download the matching ZIP; do not unpack it manually.
2. In **Plugins → Manage and Install Plugins → Install from ZIP**, select the
   package matching the QGIS major version. Enable qfit and restart QGIS if
   replacing an already loaded version. Confirm **0.53.4** in qfit's About panel.
3. Use your normal Mapbox configuration. Check **Light** and **Outdoors** at a
   regional view, a city view and street level; pan/zoom and inspect roads,
   boundaries, names and shields. Compare the same views in QGIS 3 and 4.
4. Load representative activities and check Run/Ride/Hike visibility. Save and
   reopen the test project, checking that layers and styling remain usable.
5. Export a small atlas/PDF at your normal DPI, then compare 150 and 300 DPI at
   the same physical page/map scale. Inspect labels, roads and activity overlays
   in the actual PDFs, especially in QGIS 4.
6. Record the exact QGIS/Qt version, OS, available fonts, style, view/scale and
   export DPI with any concrete failure. Do not include access tokens in reports.

The draft release's validation section records final automated test results and
package checks. Desktop acceptance remains the maintainer's next step.
