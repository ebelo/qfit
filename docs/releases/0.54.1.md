# qfit 0.54.1 — Scoped PyQGIS enum compatibility

Patch release for the 42 legacy enum references reported by the QGIS plugin
repository Qt6 checker on 0.54.0. Resolve those references through scoped enum
members with flat SIP fallbacks for older QGIS 3 bindings in background tasks,
GeoPackage writes, layout/export and symbology adapters. Apply the same export-result convention to cover/contents export.
The binding-only resolver is shared through the existing enum-compatibility
module and imports neither QGIS nor UI widgets. No changes to task cancellation,
geometry, layout units, styling or export outcomes are intended.

## Regression coverage

- A shipped-source AST regression reproduces all 42 original findings and prevents
  these direct legacy references from returning.
- Native probes resolve the 16 affected enum members against real QGIS 3
  and QGIS 4 bindings and verify equality with their legacy aliases.
- All eight affected task adapters are constructed and cancelled using real
  QgsTask bindings, without submitting work or touching live services/databases.
- Full pure and native QGIS 3/Qt 5 and QGIS 4/Qt 6 suites remain required.

## Packages

- `qfit-0.54.1.zip`: single QGIS repository package for QGIS 3.28–4.99.
- `qfit-0.54.1-qgis3.zip`: QGIS 3.28–3.99.
- `qfit-0.54.1-qgis4.zip`: QGIS 4.0+.

All packages are built from the same immutable release tag, include a changelog
and declared setup requirements, and bundle the FIT/PDF dependencies and licenses.
The release workflow attaches checksums covering all three ZIPs. Actual automated
runtime coverage is QGIS 3.44.11/Qt 5 and QGIS 4.2.0/Qt 6, not every metadata-admitted
version. The 0.54.0 tag and assets are preserved unchanged.

Existing `.bandit` and packaged Flake8 policies are unchanged; no repository
security or Qt6 rules are disabled. Repository validation/manual approval remains
a separate step from generation of these packages.
