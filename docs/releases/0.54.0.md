# qfit 0.54.0 — Detailed activities and static route heatmaps

Release candidate for desktop acceptance in QGIS 3 and QGIS 4. Keep the GitHub
release a **draft** until the maintainer accepts the packaged desktop workflows.
This minor release collects the changes since the last published release,
**0.53.3**; the earlier **0.53.4 draft was never published**.

## Highlights

### Import and synchronize detailed activities

- Import official Strava Bulk Data Export ZIPs directly, including FIT, TCX and
  GPX originals. Archive validation, bounded parsing, provenance and deterministic
  reconciliation preserve richer geometry and local annotations. Large imports
  run in cancellable background tasks with progress and recovery diagnostics.
  [PR #1484](https://github.com/ebelo/qfit/pull/1484)
- Normal **Sync activities** now fetches recent detailed routes when available,
  defers detail requests at rate limits and retries eligible deferred activities
  on later syncs. Summary activities remain usable when details are unavailable;
  partial syncs do not falsely establish a completed-sync boundary. The separate
  backfill action is removed.
  [PR #1491](https://github.com/ebelo/qfit/pull/1491)
- Publish changed activity-derived rows incrementally after bulk import, rather
  than routinely rebuilding the complete historical dataset. Preserve atlas page
  order and numbering when changed sort keys do not reorder stable page identities;
  retain safe full-rebuild fallbacks and display their reasons.
  [PR #1489](https://github.com/ebelo/qfit/pull/1489),
  [PR #1493](https://github.com/ebelo/qfit/pull/1493)
- Refresh historical or selected Strava activity names from Database actions.
  [PR #1499](https://github.com/ebelo/qfit/pull/1499),
  [PR #1501](https://github.com/ebelo/qfit/pull/1501)

### Visualize selected activity routes

- Generate a cached static red route-usage heatmap from stored tracks. Each
  activity counts once per crossed grid cell, rather than once per recorded GPS
  sample. A fixed 10 m grid, 20 m smoothing and global normalization keep density
  values independent of canvas pan/zoom and source-layer visibility. Work runs
  in a cancellable task; the prior result remains until successful publication.
  [PR #1506](https://github.com/ebelo/qfit/pull/1506)
- Budget non-empty heatmap output tiles and avoid unnecessary smoothing work for
  sparse selections, without coarsening the grid or changing density semantics.
  [PR #1508](https://github.com/ebelo/qfit/pull/1508)
- Select multiple activity types, such as **Walk or Hike**, with the native
  checkable selector. Types combine with OR; date, distance and name filters
  combine with AND. Selections persist across restart and catalog refresh.
  [PR #1510](https://github.com/ebelo/qfit/pull/1510)
- Remove the obsolete **Any routes / Detailed routes only / Missing detailed
  routes** dropdown. Old saved choices no longer silently restrict current UI
  requests; remaining filters and lower-level compatibility APIs are preserved.
  [PR #1512](https://github.com/ebelo/qfit/pull/1512)

### QGIS compatibility and cartography

- Fix QGIS 4 narrow-dock navigation and Qt 5/6 message-box buttons. Real native
  dialog regressions cover import confirmations, completion and database clearing
  with safe defaults, bounded modal execution and isolated temporary data.
  [PR #1495](https://github.com/ebelo/qfit/pull/1495),
  [PR #1504](https://github.com/ebelo/qfit/pull/1504)
- Preserve route style categories after bulk import and release staged GeoPackage
  handles on Windows.
  [PR #1487](https://github.com/ebelo/qfit/pull/1487),
  [PR #1486](https://github.com/ebelo/qfit/pull/1486)
- Include the accepted Mapbox Light and Outdoors improvements from the unpublished
  0.53.4 draft: road widths and labels, boundary foreground/background treatment,
  language/name fallbacks, shield contrast and collision handling, plus improved
  rendering provenance and real-QGIS coverage.
  See the [historical style acceptance record](0.53.4.md).

## Packages and upgrade

| Package | QGIS metadata compatibility |
| --- | --- |
| `qfit-0.54.0-qgis3.zip` | QGIS 3.28–3.99 |
| `qfit-0.54.0-qgis4.zip` | QGIS 4.0+ |

Both packages are built from the same release revision. Automated native-runtime
validation targets QGIS **3.44.11 / Qt 5** and **4.2.0 / Qt 6**, not every older
version admitted by the metadata. Packages include `pypdf`, pinned `fitdecode`
and their license files, but do not install map fonts or QGIS/GDAL itself.

Back up representative projects and GeoPackages before testing an upgrade. In a
separate profile for each QGIS generation, use **Plugins → Manage and Install
Plugins → Install from ZIP** with the matching package. Enable qfit, restart
after replacing a loaded version, and confirm **0.54.0** in About. The release
assets include SHA-256 checksums for both ZIPs.

## Known limitations and release scope

- The wider [hybrid-ingestion roadmap (#1482)](https://github.com/ebelo/qfit/issues/1482)
  remains open. This release does not claim completion of opt-in daily scheduling,
  archive reminders or every roadmap acceptance criterion.
- Recent detailed-route coverage depends on available data, authorization and
  quota. Removing the availability filter does not mean every activity has GPS
  geometry or a complete elevation profile.
- Static heatmaps reference local cache files; cache eviction and portable project
  packaging are not implemented. Widely separated routes may use Mercator map
  metres with latitude-dependent distortion; antimeridian unwrapping is not
  implemented. Genuine tile/per-activity limits require narrower selections.
  See the [heatmap guide](../static-route-heatmap.md).
- Native basemaps remain an approximation of Mapbox GL. Accepted label, collision,
  typography and zoom/filter differences are recorded in the
  [Light assessment](../light-cartographic-assessment.md). QGIS 4 density-dependent
  PDF differences remain unresolved; no pixel-perfect parity is claimed.
- Plugin ZIPs do not bundle Barlow/Noto fonts. Desktop font availability can
  change rendering; see the [font policy](../mapbox-font-policy.md).
- No renderer or activity-processing behavior is changed by this version bump
  and release-note preparation. Historical visual evidence is not a new Windows
  desktop or final-release PDF acceptance result.

## Desktop acceptance before publication

Test the exact release ZIP in both QGIS generations, using representative data
and separate test profiles. Do not clear a production database during acceptance.

1. Install and exercise startup, Activities, Configuration and About; confirm
   version 0.54.0, resize the dock, and reopen a saved project.
2. Import a representative bulk export into a test GeoPackage, re-import it, and
   run recent sync. Check progress/cancellation, defined result counts, preservation
   of richer data and clear quota/fallback messages.
3. Apply **Walk + Hike**, date, distance and name filters. Reopen settings and
   confirm selections persist and the obsolete availability selector stays absent.
4. Generate a static heatmap, pan/zoom, repeat the same selection to reuse its
   cache, change filters and rerun analysis. Save/reopen with cache files retained.
5. Inspect Light and Outdoors at regional, city and street scales with activity
   overlays. Record available fonts and concrete differences, not inferred parity.
6. Export a small atlas/PDF at normal DPI and compare 150/300 DPI at the same
   physical scale, especially in QGIS 4. Check ordering, labels and profiles in
   the actual PDFs.
7. Record QGIS/Qt versions, OS and any concrete failure without credentials or
   private activity data. Publish only after the maintainer accepts the results.

## Automated validation

Final release-preparation PR results, exact source revision, package integrity,
runtime lifecycle checks and artifact hashes are recorded in the GitHub draft.
Required unit tests, both native QGIS suites, SonarCloud, CodeQL, plugin security,
build and exact-head review remain mandatory; desktop acceptance is separate.
